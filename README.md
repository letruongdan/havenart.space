# Haven Art

Astro 7 + Svelte 5 application with a Node server, SQLite cloud storage and account-separated IndexedDB journals.

## Development

Requires Node 22.12 or newer. Run `npm ci`, then `npm run dev`. The root page and APIs require the Node server; this project cannot be deployed by uploading only `dist/client`.

## Production

Copy `.env.example` to `.env` and set a unique `HAVEN_ADMIN_PASSWORD` of at least 12 characters. Never use the former public default credential. With no bootstrap password, a fresh database creates no admin. Existing accounts using the former default are suspended; supplying a new bootstrap password for that email replaces the known credential without deleting journals. Other existing passwords are preserved.

Run `npm run typecheck`, `npm test`, `npm run build`, `npm run verify:build`, `npm run seo:audit`, then `npm start`. The production entry is `dist/server/entry.mjs`. `npm start` reads `.env`; configure a reverse proxy with HTTPS in deployment and forward only trusted request metadata. Store SQLite on a persistent writable volume. Keep the generated `dist/client/sw.js` together with its matching server/client release. Old clients can finish using the active worker; a waiting update activates when the old pages close.

Admin media settings are stored on the server and apply to visitors through `/api/photos`. Keys are not returned by the admin settings API and must not use `PUBLIC_` or `VITE_` environment names.

## Journal privacy and migration

Notes are stored as readable text in the browser. Guest notes use the existing `haven_db` database; signed-in accounts use separate `haven_db_user_<id>` databases. Existing unowned notes remain in the guest database and are never automatically uploaded to a new account. Logout switches back to guest storage. Historical notes without an owner cannot reliably be attributed to a particular account; export/import should be deliberate on a trusted device.

Cloud sync is optional and initially disabled per account. The account dialog explains that enabling it sends this account's notes to the server, where administrators can read them. Notes are **not end-to-end encrypted**. Deletion tombstones are retained for offline devices; server maintenance clears deleted content while retaining the deletion record. Keep local JSON backups for recovery from browser storage removal. Network analytics are disabled by default; local counters contain no journal text. Server login security logs retain device/IP metadata for 90 days.

Existing legacy bearer tokens are no longer accepted. Sign in again after upgrading. New sessions expire after 24 hours and are revoked by logout/password reset. Backup restore never restores bearer sessions.

## Backups and rollback

The authenticated admin backup exports all users, journal entries, feedback, traffic sessions and settings. Restore validates version 2 and merges all those tables in one transaction. A restore maps existing users by email and does not reactivate exported bearer sessions. Backups contain password hashes and provider configuration: keep them in private storage.

For an exact server disaster-recovery snapshot, stop the server before copying SQLite, or use SQLite's online backup mechanism. Do not copy only an active WAL-mode `.db` file. Test a restore on a separate path before relying on it. Preserve the persistent data volume during frontend rollback; schema migrations and new owner namespaces must be considered before using an older application version.

## Media

All 27 shipped music tracks are independently synthesized Haven Soundscapes originals under CC0, generated by `npm run media:generate` (requires an existing FFmpeg installation). The generator updates the complete checksum ledger. No commercial recordings or imitations of specific compositions are shipped. Old local recordings are preserved in the ignored `data/media-quarantine/2026-10-03` folder when upgrading this workspace; they are excluded from public/build output.

Four bundled classical paintings have source/license links in `public/credits.json` and `/media-provenance`. The Hasui file and unverified handwritten hotlink collections are excluded from the active release catalog. Dynamic Wikimedia content must expose an accepted license. Visitors see attribution links for the displayed artwork.

## Verification

`npm run typecheck` runs TypeScript, Astro and Svelte checkers. `npm run verify:build` starts an isolated production server and checks real HTTP routes, English output, invalid tokens, logout revocation, guest feedback and precache output. It saves rendered HTML for the SEO audit. Unit/integration tests mock external network calls and cover account switching, deletion, draft close, backup round-trip, media errors and WebGL fallback.

The review and remediation record are in `docs/reviews/`. Local verification does not constitute deployment or production load testing.
